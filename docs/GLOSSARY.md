# Glossary

Use these words in code, UI text, docs and pull requests.

- **Disagreement with the SRS** (§1.3): fix one of the two in a PR.
- **A word used two ways:** add a row here.
- **Names in the "In code" column** are the ones to use when a table, column or enum is first created. The design doc that creates each one confirms it.

| Term                        | Meaning                                                                                                                                               | In code                                                             | Don't say                             |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------- |
| Space                       | A venue a Host lists (café, library, co-working space)                                                                                                | `spaces`                                                            | venue, hub, listing                   |
| Zone                        | A named area inside a Space (quiet desks, rooms)                                                                                                      | `zones`                                                             | area, section                         |
| Unit                        | The smallest thing a Seeker can hold: a seat, a standing desk, or a whole room with a capacity                                                        | `units`, `unit_type`                                                | desk, spot, slot                      |
| Seat map                    | The Host-built snap-grid layout of a Space's units                                                                                                    | `seat_map`                                                          | floor plan, canvas                    |
| Seat state                  | One of Available, Pending Payment, Reserved, Occupied, and nothing else (D-004). Worked out from the hold or the Host-set state, never stored (D-046) | `available`, `pending_payment`, `reserved`, `occupied`              | Maintenance, booked, free             |
| Host-set state              | The state a Host last gave a unit by hand: Available, Reserved or Occupied. It is the seat state while no hold is active (D-046)                      | `units.host_state`                                                  |                                       |
| Reservation                 | The row that records a Seeker's hold on one unit                                                                                                      | `reservations`                                                      | booking                               |
| Hold                        | A reservation that is still active: Pending Payment, Reserved or Occupied                                                                             | active reservation                                                  | booking                               |
| Reservation status          | `pending_payment`, `reserved` or `occupied` while it is a hold; `expired`, `no_show`, `completed` or `cancelled` once it ends (D-046)                 | `reservation_status`                                                |                                       |
| Payment status              | `pending`, `paid`, `forfeited` or `refunded` (SRS §3.8). An unpaid hold that ends leaves its payment `pending` (D-046)                                | `payment_status`                                                    | expired (for a payment)               |
| Reserve-now                 | Holding only a unit that is open at that moment; no future bookings (D-001)                                                                           |                                                                     | book ahead, schedule                  |
| Payment window              | How long a unit stays Pending Payment before it returns to Available (FR-2.2). Set by the system (D-049)                                              | `payment_window`; a hold's `payment_window_ends_at`                 | hold timer                            |
| Wait window                 | The time a paid, Reserved unit is kept while the Seeker travels. The Seeker picks it within the Host's bounds. SRS §1.3 calls it "Hold / Wait window" | `wait_window`; `wait_window_ends_at`; `spaces.max_wait_window`      | hold timer                            |
| Lapse                       | A payment window or a wait window running out. The lapse step records it before any read or write (D-047)                                             | `private.record_lapses`                                             |                                       |
| Reservation fee             | The sandbox fee that guarantees a hold. Forfeited on a no-show                                                                                        | `fee_amount`                                                        | price, rate                           |
| Booking token               | The unique token shown as a QR code after payment                                                                                                     | `booking_token`                                                     | ticket                                |
| Check-in                    | The Host scans or enters the booking token; Reserved becomes Occupied                                                                                 | `checked_in_at`                                                     | arrival                               |
| No-show                     | No check-in before the wait window ends. The unit is released and the fee is forfeited                                                                | `no_show`                                                           |                                       |
| Check-out                   | The Seeker leaves; Occupied becomes Available                                                                                                         | `checked_out_at`                                                    |                                       |
| Visit                       | A reservation with a check-in. Each allows one review (D-009, D-052)                                                                                  | `checked_in_at` is set                                              |                                       |
| Curated tag                 | A platform-defined tag that powers search filters                                                                                                     | `curated`                                                           | amenity (on its own)                  |
| Custom tag                  | A Host's free-text tag, shown for display and never used as a filter                                                                                  | `custom`                                                            |                                       |
| Host-updated                | The availability label saying when the Host last set a unit's state (D-051)                                                                           | `units.host_updated_at`                                             | real-time, live                       |
| Verification status         | Whether an Administrator has approved a Space for public listing: Pending, Verified or Rejected (FR-5.1)                                              | `space_status`: `pending`, `verified`, `rejected`                   | approved, active                      |
| Seeker, Host, Administrator | The three roles                                                                                                                                       | `user_role`: `seeker`, `host`, `admin`                              | user (when a role is meant)           |
| Profile                     | A signed-up person's record: their role, name and phone number. One per account, created at sign-up                                                   | `profiles`                                                          | user record, account (for the record) |
| Seeded account              | An invented test account everyone uses: `seeker@`, `host@` and `host2@example.test`, plus `admin@` locally and in CI only (D-013, D-028)              | `supabase/seed.sql`; `npm run db:accounts` on the cloud dev project | test user, dummy account              |
| Sandbox                     | The payment gateway's test mode; no real money moves                                                                                                  |                                                                     | payment (without "sandbox")           |
| User experience (UX)        | What users see, do and are told: screens, steps, wording, and empty, loading and error states. Maria decides it (D-042)                               |                                                                     | UX (for a rule the system enforces)   |
| Story, task                 | A STORY-xx issue, and a TSK sub-issue under it                                                                                                        | `STORY-01`, `TSK-01.3`                                              | ticket, card (for the issue)          |
| Shared flow                 | A flow that crosses stories, such as a reservation from its hold to its check-in. It is drawn once, before the story designs that use it (D-044)      | `docs/flows/<name>.md`                                              |                                       |
| Worq                        | The public-facing product and application name shown in UI and browser titles (D-026)                                                                 | `Worq` (in UI / metadata)                                           | Work, WorkQ                           |
| StudyHub                    | The internal project, repository (`studyhub`), package name, and academic course codename (D-026)                                                     | `studyhub` (in repo / packages)                                     | StudyHub (in public UI copy)          |
